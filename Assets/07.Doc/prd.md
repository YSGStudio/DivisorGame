# PRD: 초등학교 5학년 대상 약수 카드게임 (유니티 웹/WebGL)

## Summary

초등학교 5학년 학생이 약수 개념을 카드게임 형태로 연습하는 유니티(Unity) 기반
웹(WebGL) 게임이다. 화면에는 1~25 범위의 목표 숫자 카드가 여러 장 동시에
노출되고, 플레이어는 손에 든 숫자 카드(약수 후보)를 제출해 목표 숫자의 약수를
전부 맞히면 점수를 얻는다. 목표 카드마다 개별 타이머가 흐르며, 빨리 클리어할수록
더 높은 점수를 받는다. 손패는 최대 10장으로 제한되고, 카드를 길게 눌러
"버리기"(삭제) 또는 "분해하기"(두 인수의 곱으로 카드 분해)를 선택할 수 있다.
시간/턴 제한 없이 계속 진행되는 스코어 어택형 게임이며, 플레이어가 직접
종료 버튼을 눌러 끝낸다.

## Problem And Goal

- 문제: 초등학교 5학년 수학 교육과정의 "약수와 배수" 단원은 반복 연습이
  필요한데, 단순 문제집 풀이는 흥미를 끌기 어렵다.
- 목표: 카드게임 형식의 즉각적 피드백(정답/오답, 타이머, 점수)을 통해
  학생이 재미있게 약수 개념을 반복 연습하도록 돕는다.
- 성공 기준: 학생이 별도 설명 없이도 목표 숫자와 손패 숫자만 보고
  "이 손패 카드가 목표 숫자의 약수인지"를 스스로 판단하며 게임을
  끝까지(종료 버튼을 누를 때까지) 이어갈 수 있다.

## Users And Use Cases

- 주 사용자: 초등학교 5학년 학생 (약 만 10~11세), 혼자 웹브라우저로 플레이.
- 사용 맥락: 학교/가정 PC 또는 노트북의 웹브라우저에서 WebGL 빌드를
  모니터 화면 전체(또는 브라우저 창)에 맞춰 플레이. 별도 로그인 없이
  바로 시작.
- 핵심 사용 시나리오:
  1. 게임을 열면 목표 숫자 카드 4장과 손패 카드 몇 장이 바로 보인다.
  2. 손패에서 약수라고 생각되는 카드를 목표 카드에 제출한다.
  3. 정답이면 카드가 사라지고 점수가 오르며, 그 목표의 약수를 모두
     맞히면 새 목표 카드가 등장한다.
  4. 손패가 부족하면 "카드 가져오기"를 눌러 채운다.
  5. 당장 쓸모없는 카드는 버리거나, 큰 수 카드를 인수 두 개로
     쪼개어(분해) 필요한 약수 카드를 확보한다.
  6. 원하는 만큼 플레이한 뒤 종료 버튼으로 게임을 마친다.

## Pre-Work

- 새로 시작하는 유니티 프로젝트로, 참고할 기존 코드베이스가 없다.
  (`context-notes.md`에 "해당 없음"으로 명시)
- 진행 전 확정이 필요한 사항은 이미 사용자 확인을 거쳤다(아래 확정 규칙 참고):
  - 목표 숫자 하나를 클리어하려면 그 수의 약수를 전부 제출해야 한다.
  - 목표 숫자 카드는 동시에 여러 장(기본 4장) 노출된다.
  - 게임은 스코어 어택형으로, 플레이어가 종료 버튼을 눌러야 끝난다.

## Non-Goals

- 멀티플레이어/실시간 대전, 서버 기반 랭킹·리더보드 기능은 만들지 않는다.
- 로그인/회원가입, 계정별 데이터 저장은 만들지 않는다.
- 안드로이드/iOS 네이티브 빌드는 다루지 않는다(WebGL 빌드만 대상).
- 최고 점수 영구 저장(재접속 후에도 남는 기록)은 이번 범위에 포함하지
  않는다. 세션 내 점수만 다룬다. (필요 시 `Risks And Open Decisions`
  참고 후 별도 PRD로 확장)
- 난이도 자동 조절, 튜토리얼 애니메이션 등 부가 연출은 다루지 않는다.
  최초 진입 시 간단한 안내 텍스트 한 줄 정도만 포함한다.
- 사운드는 정답/오답/클리어 등 최소 효과음만 다루며, 배경음악(BGM)
  제작은 범위 밖이다(무음 또는 임시 플레이스홀더 허용).

## Requirements

1. **R1 (목표 카드 초기화)**: 게임 시작 시 보드에 목표 숫자 카드를
   동시에 4장(Inspector에서 조정 가능한 값, 기본값 4) 노출한다. 각
   카드의 숫자는 1~25 범위에서 무작위로 생성하며 중복을 허용한다.
2. **R2 (목표별 개별 타이머)**: 각 목표 카드는 화면에 등장한 시점부터
   0초에서 시작해 초 단위로 증가하는 타이머를 개별로 가지며, 카드 위에
   경과 시간을 표시한다.
2-1. **R2-1 (약수 제출 진행 표시)**: 각 목표 카드 위에는 그 숫자의 전체
   약수 개수 대비 지금까지 정답으로 제출된 약수 개수를 `제출한 개수/전체
   약수 개수` 형식(예: 5의 약수는 1, 5로 총 2개이므로 하나만 맞혔다면
   "1/2")으로 표시한다. 정답을 제출할 때마다 이 표시가 즉시 갱신되며,
   전체 약수를 모두 맞히면(예: "2/2") 해당 목표가 클리어된다(R7).
3. **R3 (손패 초기 지급 및 상한)**: 게임 시작 시 손패에 카드 5장을
   자동 지급한다(범위 1~25, 무작위). 손패는 최대 10장을 초과할 수 없다.
4. **R4 (카드 가져오기)**: 화면의 "카드 가져오기" 버튼을 누르면 1~25
   범위의 무작위 숫자 카드 1장이 손패에 추가된다. 손패가 이미 10장이면
   버튼이 비활성화되고 더 이상 카드를 받을 수 없다.
5. **R5 (카드 제출/정답 처리)**: 플레이어가 손패 카드를 목표 카드에
   제출했을 때, 그 값이 목표 숫자의 약수이면서 해당 목표에서 아직
   제출되지 않은 값이면 정답으로 처리한다. 목표 카드의 "확보한 약수
   목록"에 표시되고, 제출한 카드는 손패에서 제거된다.
6. **R6 (오답 처리)**: 제출한 값이 목표 숫자의 약수가 아니거나 이미
   그 목표에 제출된 값이면 오답으로 처리한다. 카드는 손패에 그대로
   남고(삭제되지 않음), 점수 차감 없이 오답 피드백(시각/음향)만
   표시한다.
7. **R7 (목표 클리어 판정)**: 목표 숫자의 모든 약수가 제출되면 해당
   목표 카드는 "클리어" 상태가 되어 보드에서 사라지고 점수가 확정된다.
8. **R8 (점수 계산)**: 목표 클리어 시 획득 점수는 다음 공식으로
   계산한다: `점수 = max(기본점수 - 경과초 × 초당감점, 최소점수)`,
   `기본점수 = 10 × 약수개수`, `초당감점 = 2`, `최소점수 = 5 × 약수개수`.
   세 숫자(10, 2, 5)는 밸런싱을 위해 코드 상수가 아닌 Inspector 노출
   값으로 구현한다.
9. **R9 (신규 목표 자동 생성)**: 목표 카드가 클리어되면 그 자리에 곧바로
   (연출 지연은 1초 이내) 새로운 무작위 목표 숫자 카드(1~25)가 등장하고
   새 타이머가 0부터 시작한다. 이 과정은 게임이 끝날 때까지 반복된다.
10. **R10 (롱프레스 메뉴)**: 손패 카드를 일정 시간 이상 누르고 있으면
    (PC 환경 기준 마우스 좌클릭 홀드 0.5초 이상) "버리기" / "분해하기"
    두 선택지가 있는 팝업 메뉴가 나타난다.
11. **R11 (버리기)**: 팝업에서 "버리기"를 선택하면 해당 카드가 손패에서
    영구히 제거된다.
12. **R12 (분해하기)**: 팝업에서 "분해하기"를 선택하면 다음 규칙을
    따른다.
    - 카드 값이 합성수(1과 자기 자신 외의 약수가 존재하는 수)일 때만
      "분해하기"가 활성화된다. 소수 또는 1인 카드는 비활성화(회색 처리)
      되어 선택할 수 없다.
    - 분해 가능한 인수쌍이 2개 이상이면(예: 12 = 2×6 또는 3×4) 선택
      가능한 인수쌍 목록을 보여주고 플레이어가 하나를 고른다.
    - 인수쌍을 선택하면 원래 카드는 제거되고, 선택한 두 인수 값의 카드
      2장이 손패에 추가된다.
    - 분해 결과 손패 수가 최대치(10장)를 초과하게 되는 경우
      "분해하기" 자체를 비활성화하고 안내 문구를 보여준다(현재 손패가
      9장 이하일 때만 분해 가능).
13. **R13 (상시 UI 표시)**: 화면 상단(또는 지정 위치)에 누적 점수,
    현재 손패 수/최대치(예: "7/10"), 종료 버튼을 항상 표시한다.
14. **R14 (게임 종료)**: 종료 버튼을 누르면 확인 절차 없이(또는 간단한
    확인 팝업 후) 게임을 종료하고, 최종 누적 점수와 클리어한 목표 수를
    보여주는 결과 화면으로 전환한다.
15. **R15 (모니터 화면 대응)**: WebGL 빌드는 1920×1080(16:9) 해상도를
    기준으로 설계하고, Canvas Scaler를 통해 다양한 모니터/브라우저
    창 크기에서도 비율이 깨지지 않고 화면에 맞춰 확대/축소되도록
    한다.

## Acceptance Criteria

- **AC1 (R1)**: 게임을 새로 시작하면 보드에 목표 숫자 카드가 정확히
  4장 나타나며, 각 카드 값이 1~25 범위 내인지 사람이 확인한다.
- **AC2 (R2)**: 목표 카드가 등장한 순간부터 화면의 타이머 숫자가 0에서
  시작해 1초 간격으로 증가하는지 사람이 시각적으로 확인한다.
- **AC2-1 (R2-1)**: 목표 카드 등장 직후 표시가 `0/전체 약수 개수`(예:
  목표가 12면 "0/6")로 시작하는지, 정답을 하나 제출할 때마다 분자가
  1씩 즉시 올라가는지, 분자와 분모가 같아지는 순간(예: "6/6") 해당
  목표가 클리어되어 사라지는지 확인한다.
- **AC3 (R3, R4)**: 게임 시작 직후 손패가 5장인지 확인하고, "카드
  가져오기"를 눌러 손패가 10장이 될 때까지 계속 늘어나는지, 10장에서
  버튼이 비활성화되는지 사람이 확인한다.
- **AC4 (R5, R7)**: 목표 카드가 예를 들어 12일 때, 1·2·3·4·6·12를
  순서 상관없이 모두 제출하면 카드가 손패에서 사라지고 목표 카드가
  클리어되어 보드에서 제거되는지 확인한다(자동화 테스트로 약수 판정
  로직 단위 검증 + 사람의 화면 확인).
- **AC5 (R6)**: 약수가 아닌 값(예: 목표가 12인데 5를 제출)을 제출하면
  카드가 손패에 그대로 남아 있고 오답 피드백이 나타나는지, 점수가
  차감되지 않는지 확인한다.
- **AC6 (R8)**: 목표 클리어 시 점수가 공식(`기본점수 - 경과초×2`,
  최소점수 하한)대로 계산되는지 단위 테스트로 검증한다(예: 약수 4개인
  숫자를 3초 만에 클리어 시 점수 = max(40-6, 20) = 34).
- **AC7 (R9)**: 목표 카드를 클리어한 직후 같은 자리(또는 빈 자리)에
  새 목표 숫자 카드가 자동으로 나타나고 새 타이머가 0부터 시작하는지
  확인한다.
- **AC8 (R10, R11)**: 손패 카드를 길게 누르면 "버리기/분해하기" 팝업이
  뜨고, "버리기"를 선택하면 해당 카드가 손패에서 사라지는지 확인한다.
- **AC9 (R12)**: 합성수 카드(예: 12)를 분해하면 인수쌍 선택 UI가 뜨고,
  하나를 고르면 원래 카드가 사라지고 선택한 두 인수 카드가 손패에
  추가되는지 확인한다. 소수 카드(예: 7)나 1 카드는 분해하기 옵션이
  비활성화되어 있는지 확인한다. 손패가 9장을 초과한 상태에서는
  분해하기가 비활성화되는지 확인한다.
- **AC10 (R13, R14)**: 점수/손패 수 UI가 실시간으로 갱신되는지, 종료
  버튼을 누르면 최종 점수와 클리어 수가 표시된 결과 화면으로
  전환되는지 확인한다.
- **AC11 (R15)**: 브라우저 창 크기를 다양하게(예: 1920×1080,
  1366×768) 조정해도 UI 비율이 깨지지 않고 카드가 잘리지 않는지
  사람이 확인한다.

## Verification - Agent

- 약수 판정 로직(어떤 수가 특정 목표의 약수인지, 목표의 전체 약수
  목록 생성)에 대한 C# 단위 테스트(Unity Test Framework, Edit Mode)를
  작성하고 통과시킨다. 1, 소수, 완전제곱수(예: 16), 약수가 많은 수
  (예: 24)를 포함한 경계값을 검증한다.
- 점수 계산 함수에 대한 단위 테스트(정상 케이스, 최소점수 하한 케이스)
  를 작성하고 통과시킨다.
- 카드 분해 시 유효한 인수쌍만 후보로 제시되는지(1×n, n×1 제외,
  a≤b 형태 중복 제거) 단위 테스트로 검증한다.
- 손패 최대 10장 제한 로직(카드 가져오기 차단, 분해 시 초과 방지)을
  단위 테스트로 검증한다.
- Unity 에디터에서 콘솔 에러/경고 없이 Play Mode 진입 및 기본 플로우
  (목표 등장 → 카드 제출 → 클리어 → 신규 목표 등장)가 예외 없이
  동작하는지 확인한다.

## Verification - Human

## Technical Structure And Changes

- **기술 스택 (기본값에서 벗어남)**: 사용자가 명시적으로 유니티(Unity)
  + WebGL을 요청했으므로, 이 PRD는 기본 스택(React + Next.js) 대신

  1920×1080, Match 0.5) 사용.
- **입력 처리**: 마우스 클릭(제출은 손패 카드 선택 → 목표 카드 클릭

  상태(손패, 목표 카드, 점수, 타이머)는 모두 런타임 메모리(C# 객체)에서
  관리하며, 세션 종료(새로고침) 시 초기화된다. 영구 저장이 필요해지면

  - `GameManager`: 전체 게임 상태(점수, 진행 여부), 목표 카드 슬롯

  - `ScoreCalculator`: 점수 공식 계산(단위 테스트 대상, 순수 함수로

## Risks And Open Decisions

- **미확정: 카드 제출 조작 방식** — 드래그 앤 드롭 vs 클릭-클릭(손패
  선택 후 목표 클릭) 중 택1. 5학년 학생 대상으로는 클릭-클릭 방식이
  구현 난이도와 조작 실수 가능성 면에서 더 안전하다고 보고 잠정
  기본값으로 채택했다(R5, T5). 드래그 앤 드롭을 원하면 T5 재설계
  필요.
- **미확정: 최고 점수 영구 저장 여부** — 이번 범위는 세션 내 점수만
  다룬다(Non-Goals 참고). 재접속 후 기록 유지가 필요하면 PlayerPrefs
  기반 저장을 별도 태스크로 추가해야 한다.
- **미확정: 점수 공식 상수 값(10, 2, 5)** — 초기 잠정값이며 실제
  플레이테스트 후 밸런싱 조정이 필요할 수 있다. Inspector 노출 값으로
  구현해 코드 수정 없이 조정 가능하게 한다(R8).
- **위험: 오답 반복 시 재미 저하** — 특정 목표(예: 24처럼 약수가
  8개인 수)는 손패 구성에 따라 완료가 오래 걸릴 수 있다. 목표 카드
  동시 노출 수(기본 4장)와 카드 가져오기를 통해 완화하되, 플레이테스트
  후 목표 숫자 범위나 동시 노출 수 조정이 필요할 수 있다.
- **위험: 분해하기의 손패 초과 규칙 이해도** — "손패 9장 이하에서만
  분해 가능"이라는 규칙이 학생에게 직관적이지 않을 수 있다. 버튼
  비활성화 시 안내 문구(예: "손패가 가득 차 분해할 수 없어요")를
  명확히 노출해야 한다(T9).
